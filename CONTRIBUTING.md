# Contributing

## Issue requirements

Every task should:

- start with an action verb;
- describe one deliverable;
- have one owner;
- include a measurable done condition; and
- link evidence before it is closed.

## Branches and pull requests

Use **issue-number-short-description** for branch names.

Pull requests should be small enough to review, reference the related issue, and
include verification evidence. Write **Closes #number** only when the pull request
fully completes the issue.

## Board rules

The team board uses exactly three columns: **To Do**, **Doing**, and **Done**.

Each member may have only one card in **Doing**. A blocked card stays visible,
receives the **Blocked** label, and includes a comment describing the blocker and
the next action.

## Reviews

Reviewers should check:

- the change matches the issue;
- links and navigation work;
- formatting is readable on phone and desktop;
- accessibility basics are present; and
- documentation reflects the result.
